Q: Describe an AI-powered product feature you've recently shipped. Which techniques and technologies were used to build the feature? How did you evaluate and improve its quality? (required)

At Coordinator (2026), an AI sports-coaching product, I shipped the request path behind the in-app assistant: a tiered agent runtime that decides how much machinery each request gets.

Techniques and technologies: the runtime is Python. The model acts through Go agent tools with exact contracts: write/edit tools for the user's workspace apps and read-only tools for data across apps. Narrow, typed tools made the model's actions testable and easy to review. The runtime also handles group-scoped memory with pruning, and voice turns (Whisper speech-to-text in, TTS out). Fine-tuned models are served with vLLM on H100s.

Evaluation and improvement: I timed the tiers on real requests instead of assuming the agent loop was needed. A single-shot path was 4-6x faster for a large share of requests, so I added it as a fourth tier and routed those requests to it. Quality came from reviewed turns: users and coaches reviewed model turns, a pipeline turned those into training data, and the feedback-retraining loop fed the next fine-tune. For the vision feature (formation detection from game film) I built a scoring harness and tuned thresholds and frame preprocessing against it before changing anything in production.
